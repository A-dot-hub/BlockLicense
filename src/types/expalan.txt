Part 1: How to Explain the Project to Your Professor
1. The Elevator Pitch (First 30 Seconds)

"Good morning Professor. My project is BlockLicense, a decentralized software authenticity, ownership, and anti-piracy verification system built on the Ethereum Virtual Machine (EVM).

Traditional software licensing relies on centralized vendor activation servers and static license keys. These suffer from three major vulnerabilities: binary tampering (hackers injecting malware or DRM cracks into binaries), unauthorized secondary reselling (double-spending licenses), and centralized vendor record tampering.

BlockLicense solves this by separating concerns between off-chain metadata and on-chain immutable smart contract invariants, anchoring a 32-byte SHA-256 software digest directly onto the blockchain."

2. The Core Blockchain Technical Concepts (Professor Checklist)

Solving the Double-Spending Problem in Software Resale	License ownership is represented by an Ethereum wallet address (address owner). Transferring requires msg.sender == lic.owner.	In standard web licensing, a user can sell their license key to buyer A and keep using or selling it to buyer B. The blockchain enforces atomic ownership transfer.

Decentralized Revocation & Auditability	When an authority revokes a rogue seat, a LicenseRevoked event is emitted. Any third-party auditor can inspect event logs from Genesis block to the latest block.	Database rows can be quietly deleted or modified with UPDATE / DELETE statements without trace.

Part 3: Anticipated Professor Viva Questions & Winning Answers
Q1: "Why blockchain and not a regular database with digital signatures?"

Answer: "In a centralized database, the vendor controls the record. If the vendor goes out of business, changes terms, or gets hacked, license validity records can be revoked, lost, or silently changed. With a smart contract, ownership is sovereign and non-custodial: once issued, the record exists across the distributed ledger without single points of failure."

Q2: "What consensus algorithm is used?"

Answer: "In our local development environment, Hardhat runs an EVM implementation using automated instant proof-of-authority execution. In production deployment, this contract targets Ethereum mainnet or Layer-2 rollups like Arbitrum/Polygon, utilizing Proof-of-Stake (PoS) consensus for energy efficiency and cryptographic finality."

Q3: "How does the software executable verify the license when running offline?"

Answer: "The application executable includes a lightweight client-side verification engine. Upon initialization, it computes its own executable SHA-256 digest and compares it against a vendor-signed payload or cached on-chain state, allowing offline cryptographic validation without constant internet polling."
